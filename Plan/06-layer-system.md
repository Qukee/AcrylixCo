# Layer System

The layer system is the core technical primitive of the designer. Every design — every template, every customer composition — is built from layers.

## Layer types

Each piece typically has 2 layers, sometimes 3:

| Layer | Always present? | Role |
| --- | --- | --- |
| **Base layer** | Yes | The bottom acrylic sheet. Generated by [offset-outline](./07-offset-outline-generation.md) from the foreground. |
| **Foreground layer** | Yes | The top acrylic piece — usually the text or main shape the customer is buying. |
| **Accent layer** | No | A third layer for compositions like "script name over block letter" — effectively a second foreground element above the first. |

## Per-layer properties

Each layer carries independent properties:

- **Content** — text string (for text layers) or a vector shape (for shape layers).
- **Font** — applies to text layers; from the [typography library](./09-typography.md).
- **Material** — a (color + finish) pair from the [material & finish library](./08-material-finish-library.md).
- **Thickness** — physical thickness of the acrylic sheet, in millimetres.
- **Geometric transforms** — position, rotation, scale, where applicable (constrained by the template).

## Why separate layers (not a single styled shape)

Because each layer is a physically separate acrylic piece. The data model has to mirror manufacturing: the laser cutter receives one vector outline per layer, cuts each from its own sheet of the chosen material, and we bond them together.

This is why "color" alone is not enough as a property — each layer is a piece of physical material with a real thickness and finish.

## Relationship to the offset-outline engine

The base layer is **derived** from the foreground (and optionally accent) layer geometry, not authored independently. See [offset-outline generation](./07-offset-outline-generation.md) for the rules.

Customers may choose:

- **Unified base** — a single base shape that hugs the union of all foreground elements.
- **Per-element base** — each foreground element gets its own base.

This choice is per-template-default but customer-overridable.

## Open questions

- Are there compositions that need more than 3 layers? (E.g. a 4-layer "stacked frame" effect.) Initial answer is no, but worth confirming.
- Should layer **thickness** be customer-controlled or fixed per material? Currently leaning fixed-per-material to simplify production.
- Z-ordering — is it always base → foreground → accent, or are there compositions where this needs to vary?
